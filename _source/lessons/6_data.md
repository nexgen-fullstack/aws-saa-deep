> 🖼️ **Образ.** **RDS** — найнятий адміністратор бази даних: сам встановлює, латає, робить бекапи. **Multi-AZ** — дублер у запасній кімнаті: синхронно записує все, але з клієнтами не говорить; основний знепритомнів — дублер за хвилину-дві стає до роботи. **Read replicas** — помічники, які лише відповідають на запитання (читання) і можуть трохи відставати.

**RDS:**

- MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2. Доступу до операційної системи немає (крім RDS Custom).
- **Multi-AZ** — для **виживання**: синхронна копія в іншій AZ, автоматичне перемикання (зазвичай 60–120 с), та сама адреса підключення.
- **Read replicas** — для **читання**: асинхронні, до 15, можуть бути в іншому регіоні (і стати основною базою під час аварії). Застосунок сам надсилає читання на репліку.
- Бекапи на 1–35 днів + відновлення на будь-яку мить (point-in-time). Відновлення завжди створює **нову** базу з новою адресою.
- **RDS Proxy** — секретар, що тримає телефонні лінії: пул з'єднань для тисяч функцій Lambda і швидше перемикання.

**Aurora** — «турбо-версія» MySQL і PostgreSQL від AWS:

- 6 копій даних у 3 AZ, сховище саме росте до 256 TiB.
- До 15 реплік на спільному сховищі, перемикання приблизно за 30 с, репліки можна додавати автоматично.
- Входи: **writer** (запис), **reader** (читання, розподіляє між репліками), **custom** (окремий вхід, напр. для аналітиків).
- **Global Database** — філії в інших регіонах (до 10) з відставанням менше секунди; перемикання менш ніж за хвилину.
- **Serverless v2** — «авто з автоматичною коробкою»: сам додає потужність і може «заснути» до нуля, тоді платиш лише за сховище.
- **Backtrack** — перемотка назад без відновлення з бекапу (лише Aurora MySQL). **Cloning** — миттєва копія для тестів. **Babelfish** — розуміє мову SQL Server (T-SQL).

#### 💡 Запам'ятай

- **Multi-AZ — для виживання. Read Replica — для читання.**
- Aurora: **«6 копій у 3 AZ»**, 15 реплік, Global Database — менше секунди.
- Lambda + RDS → **RDS Proxy**.

#### 🎯 Як питають на іспиті

- Звіти аналітиків гальмують основну базу → **Read replica**
- Автоматичне перемикання бази в іншу AZ → **RDS Multi-AZ**
- Реляційна база переживе падіння регіону, RPO ~1 с → **Aurora Global Database**
- База простоює вночі й на вихідних → **Aurora Serverless v2**
- Переїзд з SQL Server без переписування T-SQL → **Babelfish for Aurora PostgreSQL**

#### ⚠️ Не плутай

- Standby у Multi-AZ (звичайний інстанс) не читається.
- Відновлення зі знімка — це нова база з новою адресою.

> 🖼️ **Образ.** **DynamoDB** — гігантська картотека: знаєш номер картки (ключ) — отримуєш її за мілісекунди, навіть коли запитів мільйони. **DAX** — кишенька з найчастішими картками (мікросекунди). **ElastiCache** — записник на столі: не треба щоразу бігти в архів (у базу).

**DynamoDB:**

- Serverless NoSQL: мілісекунди на будь-якому масштабі, дані в кількох AZ автоматично. Одна «картка» (елемент) — до 400 KB.
- Ключ — **partition key** (номер ящика) + за потреби sort key. Обирай ключ з багатьма різними значеннями (userId), інакше буде «гарячий» ящик і throttling.
- Оплата: **on-demand** (за кожен запит — для непередбачуваного трафіку) або **provisioned** (абонемент на RCU/WCU + auto scaling — для стабільного).
- **Global Tables** — картотека в кількох регіонах із записом у будь-якому.
- **Streams** — стрічка змін → Lambda. **TTL** — картки самі знищуються з часом. **PITR** — відновлення на будь-яку секунду за 35 днів.
- Складних JOIN немає — це не реляційна база.

**Кеш:**

- **ElastiCache (Redis OSS / Valkey)** — реплікація, Multi-AZ, складні структури: sorted sets для лідербордів, сесії.
- **Memcached** — простий швидкий кеш без реплікації.
- Кеш вимагає змін у коді («спершу глянь у записник»). DAX — майже без змін, але тільки для DynamoDB.

**Спеціальні бази — «кожній задачі своя»:**

- **Neptune** — карта знайомств (графи: «друзі друзів», шахрайські зв'язки).
- **DocumentDB** — сумісна з MongoDB. **Keyspaces** — з Cassandra. **Timestream** — щоденник показників за часом (IoT).
- **Redshift** — аналітичне сховище (наступний урок). **OpenSearch** — пошуковик по твоїх даних.

#### 💡 Запам'ятай

- **Ключ-значення, мілісекунди, serverless → DynamoDB. Мікросекунди для DynamoDB → DAX.**
- Лідерборд → Redis/Valkey sorted sets.
- Граф → Neptune. MongoDB → DocumentDB. Cassandra → Keyspaces. Часові ряди → Timestream.

#### 🎯 Як питають на іспиті

- Кошики, сесії, профілі гравців на мільйонах запитів → **DynamoDB**
- Запис з низькою затримкою у двох регіонах → **DynamoDB Global Tables**
- Реагувати на кожну зміну в таблиці → **DynamoDB Streams + Lambda**
- Автоматично видаляти сесії через 24 год → **TTL**
- Лідерборд у реальному часі → **ElastiCache for Redis/Valkey**

#### ⚠️ Не плутай

- DAX — лише для DynamoDB; для RDS — ElastiCache.
- «Без змін коду» — не ElastiCache: йому потрібна логіка кешування в застосунку.

> 🖼️ **Образ.** **Data lake** — озеро, куди стікають усі річки даних у сирому вигляді (S3). **Glue** — бібліотекар: складає каталог, що де лежить, і наводить лад (ETL). **Athena** — питаєш SQL прямо в озера. **Redshift** — склад з упорядкованими полицями для звітів. **Quick** — вітрина з дашбордами для керівників.

**Потоки:**

- **Kinesis Data Streams** — річка в реальному часі: кілька споживачів, перемотка (replay) до 365 днів.
- **Data Firehose** — трубопровід: сам складає потік у S3, Redshift чи OpenSearch і може перетворити JSON у Parquet.
- **Managed Service for Apache Flink** — аналіз потоку «на льоту» (вікна часу, аномалії).
- **MSK** — керований Kafka для наявних Kafka-застосунків.

**Озеро і запити:**

- **Glue** — crawler визначає схему, **Data Catalog** зберігає опис таблиць, ETL перетворює CSV у Parquet.
- **Athena** — SQL по файлах у S3 без серверів; платиш за прочитані дані. CSV — щоб знайти одне слово, читаєш усю книгу; **Parquet з партиціями** — одразу відкриваєш потрібну главу. Тому в рази дешевше і швидше.
- **Redshift** — сховище даних для важкої регулярної аналітики; **Spectrum** — «зі складу заглянути в озеро»; zero-ETL з Aurora.
- **EMR** — важкий завод Spark/Hadoop (task-вузли на Spot — дешево).
- **OpenSearch** — пошук і аналіз логів.
- **Amazon Quick** (колишній QuickSight) — дашборди.
- **Lake Formation** — охорона озера: доступ аж до окремих колонок і рядків.

[🗺️ Схема: data lake](#fig-datalake)

#### 💡 Запам'ятай

- Реальний час + перемотка → **Kinesis Data Streams**. Просто доставити → **Firehose**.
- Разові SQL по S3 → **Athena**. Регулярна важка аналітика → **Redshift**.
- Дешевше в Athena → **Parquet + стиснення + партиції**.

#### 🎯 Як питають на іспиті

- Кілька застосунків читають клікстрім у реальному часі → **Kinesis Data Streams**
- Складати потік у S3 як Parquet без коду → **Data Firehose**
- SQL по логах у S3 без серверів → **Athena**
- Права до окремих колонок і рядків у data lake → **Lake Formation**
- Дашборди для бізнесу → **Amazon Quick**

#### ⚠️ Не плутай

- Firehose не має перемотки і власних споживачів.
- Athena — не сховище: дані лишаються в S3.

> 🖼️ **Образ.** Набір готових «органів чуття» для твого застосунку. **Rekognition** — очі. **Transcribe** — вуха. **Polly** — голос. **Translate** — перекладач. **Comprehend** — читач, що розуміє настрій і зміст тексту. **Textract** — бухгалтер, що читає документи й таблиці. **Lex** — співрозмовник-чатбот. **SageMaker AI** — лабораторія, де вирощують власний «мозок» (модель).

Головна думка для іспиту: якщо задача стандартна (розпізнати обличчя, перетворити мову в текст, перекласти) — бери **готовий сервіс**, знання машинного навчання не потрібні. Якщо потрібна власна модель — **SageMaker AI**.

- **Rekognition** — об'єкти й обличчя на фото і відео, модерація контенту.
- **Textract** — текст, **форми й таблиці** зі сканів і PDF (більше, ніж простий OCR).
- **Comprehend** — тональність відгуків, ключові фрази, мова, персональні дані в тексті.
- **Transcribe** — мова → текст (дзвінки, субтитри).
- **Polly** — текст → мова (озвучення). Мнемоніка: папуга Поллі говорить.
- **Translate** — машинний переклад.
- **Lex** — чатботи (голос і текст).
- **SageMaker AI** — навчити, розгорнути й обслуговувати свою модель.

Ланцюжок, який люблять на іспиті: записи дзвінків → **Transcribe** → текст → **Comprehend** (настрій) або **Translate** → **Polly** (озвучити).

А ще для фронтенду: **Amplify** — хостинг і бекенд для веб- і мобільних застосунків, **Device Farm** — тестування на сотнях справжніх телефонів.

#### 💡 Запам'ятай

- Очі — Rekognition. Вуха — Transcribe. Голос — Polly. Документи — Textract. Розуміння тексту — Comprehend.
- Власна модель — **SageMaker AI**.

#### 🎯 Як питають на іспиті

- Модерація фото користувачів → **Rekognition**
- Дані з рахунків і форм у PDF → **Textract**
- Тональність відгуків → **Comprehend**
- Субтитри з відео → **Transcribe**
- Озвучити статті → **Polly**

#### ⚠️ Не плутай

- Transcribe (мова → текст) ≠ Polly (текст → мова).
- Textract (документи, форми) ≠ Rekognition (фото і відео).
