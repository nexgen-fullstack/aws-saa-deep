> 🖼️ **Образ.** EC2 — автопрокат комп'ютерів. **Тип інстансу** — модель авто: **C** — спорткар (потужний процесор), **R** — вантажівка з великим кузовом (багато пам'яті), **I** — авто з величезним швидким багажником (диски), **P/G** — з турбіною (GPU), **T/M** — універсал на кожен день.

**Як читати назву:** `m7g.2xlarge` — сімейство **m**, покоління **7**, **g** — процесор Graviton (ARM, помітно вигідніший), розмір **2xlarge**.

**Як платити** — найважливіша тема для питань про вартість:

**Розміщення (placement groups):**

- **Cluster** — команда за одним столом: максимальна швидкість обміну між серверами (HPC), але одна «пожежа» зачепить усіх.
- **Spread** — кожен у своєму будинку: максимум 7 інстансів на AZ, для кількох критичних серверів.
- **Partition** — секції з окремими входами: сотні серверів Hadoop, Kafka, Cassandra.

**Диски і стан:**

- **EBS** — «підключений жорсткий диск», дані переживають вимкнення.
- **Instance store** — записи крейдою на дошці: найшвидше, але зникає при зупинці.
- **AMI** — «зліпок» комп'ютера для швидкого клонування; регіональний, копіюється в інші регіони.
- **Hibernate** — сон ноутбука: вміст пам'яті зберігається на диск.
- **User data** — скрипт при першому запуску; **IMDSv2** — безпечний доступ до метаданих інстансу.

#### 💡 Запам'ятай

- Spot — **2 хвилини** попередження. Spread — **7 на AZ**.
- Постійно — Savings Plans/RI. Можна переривати — Spot. Невідомо — On-Demand. Ліцензії на ядра — Dedicated Host.
- Instance store зникає, EBS — ні.

#### 🎯 Як питають на іспиті

- Нічні пакетні задачі, які можна перезапускати, найдешевше → **Spot Instances**
- 24/7 на 3 роки + свобода міняти сімейства і перейти на Fargate → **Compute Savings Plans**
- Ліцензії Windows або SQL Server прив'язані до фізичних ядер → **Dedicated Hosts**
- HPC з мінімальною затримкою між вузлами → **Cluster placement group + EFA**
- Кодування відео (навантаження на процесор) → **C-сімейство**

#### ⚠️ Не плутай

- Spot не для основної бази і не для задач без чекпоінтів.
- Вертикальне масштабування (більший інстанс) — з зупинкою. Горизонтальне (більше інстансів) — через ASG.

> 🖼️ **Образ.** Ресторан без власної кухні. **API Gateway** — офіціант: приймає замовлення, перевіряє, чи ти гість, стежить, щоб не було натовпу. **Lambda** — кухар на виклик: приходить, готує страву (до 15 хвилин), і ти платиш лише за приготоване. **DynamoDB** — холодильник, **S3** — комора.

**Lambda — головне:**

- До **15 хвилин** на виклик, пам'ять 128 MB – 10 GB (процесор росте разом з пам'яттю), 1 000 одночасних виконань за замовчуванням.
- Запускається подіями: новий файл у S3, повідомлення в SQS, запит з API Gateway, розклад EventBridge, зміни в DynamoDB.
- **Cold start** — кухар щойно прийшов і розкладає ножі. Ліки: **provisioned concurrency** (кухарі вже чекають на кухні) і **SnapStart** (Java, Python, .NET).
- Забагато з'єднань до RDS → **RDS Proxy**. Обмежити функцію → reserved concurrency.
- Довше 15 хвилин → Step Functions (розбити на кроки), ECS/Fargate або AWS Batch.

**Контейнери** — стандартні «морські контейнери» для застосунків: усередині програма з усім потрібним, і вона однаково працює будь-де.

- **ECS** — диспетчер порту від AWS (простіше). **EKS** — керований Kubernetes (якщо команда вже на K8s).
- **Fargate** — порт сам дає крани й причали: контейнери без серверів (для ECS і EKS).
- **ECR** — склад образів контейнерів.
- **Elastic Beanstalk** — ресторан під ключ: приносиш код, AWS сам ставить сервери, балансувальник і масштабування.
- **AWS Batch** — цех для великих пакетних задач будь-якої тривалості.

#### 💡 Запам'ятай

- **Lambda: 15 хвилин, 10 GB, 1 000 одночасно.**
- Cold start → provisioned concurrency або SnapStart.
- Контейнери без серверів → Fargate. Уже є Kubernetes → EKS.

#### 🎯 Як питають на іспиті

- Задача виконується 40 хвилин → **не Lambda: AWS Batch, ECS/Fargate або Step Functions**
- Serverless REST API → **API Gateway + Lambda + DynamoDB**
- Lambda вичерпує з'єднання до бази → **RDS Proxy**
- Розробники хочуть просто задеплоїти вебзастосунок → **Elastic Beanstalk**
- Різні ліміти запитів для різних клієнтів API → **API Gateway usage plans**

#### ⚠️ Не плутай

- Beanstalk не serverless — він створює EC2, просто керує ними за тебе.
- Reserved concurrency (ліміт) ≠ provisioned concurrency (прогріті середовища).

> 🖼️ **Образ.** Поліклініка. **SQS** — талончики в черзі: пацієнти (повідомлення) чекають, а лікарі (воркери) беруть по одному у своєму темпі. **SNS** — гучномовець: одне оголошення чують усі одразу. **EventBridge** — диспетчерська з правилами «яка подія — куди». **Step Functions** — головлікар з покроковим планом лікування.

**SQS** (pull — «забирай сам»):

- Розв'язує компоненти й згладжує піки: замовлення не губляться, навіть якщо бекенд упав (повідомлення зберігаються до 14 днів).
- **Visibility timeout** — талон у руках лікаря: інші його не бачать. Не встиг за відведений час — талон повертається в чергу, і його обробить хтось іще. Ліки від «обробки двічі» — збільшити timeout.
- **Standard** — майже без лімітів, але можливі дублі й зміна порядку. **FIFO** — строгий порядок і без дублів.
- **DLQ** — окрема папка для «безнадійних» талонів після кількох невдалих спроб.
- Long polling — лікар чекає до 20 секунд, а не смикає реєстратуру щосекунди (дешевше).

**SNS** (push — «кажу всім»):

- Одне повідомлення → багато підписників: SQS, Lambda, email, SMS, HTTP.
- SNS — не черга: «на потім» нічого не зберігає. Тому класика — **fan-out**: SNS → кілька SQS, у кожного обробника своя поштова скринька.

**EventBridge** — події від AWS, твоїх застосунків і SaaS (Zendesk, Shopify…) → правила → цілі. Плюс **Scheduler** — будильник (cron) без серверів.

**Step Functions** — покроковий процес з повторами, розгалуженнями і паузою на ручне схвалення. Standard — до року; Express — до 5 хвилин, для величезних потоків.

**Kinesis Data Streams** — річка даних з пам'яттю: кілька заводів беруть воду з тієї ж річки в реальному часі й можуть «перемотати» назад. **Data Firehose** — трубопровід, що сам доставляє потік у S3, Redshift чи OpenSearch.

**Amazon MQ** — перекладач для старих застосунків на JMS, AMQP чи MQTT (RabbitMQ, ActiveMQ) без переписування коду.

[🗺️ Схема: fan-out SNS → SQS](#fig-fanout)

#### 💡 Запам'ятай

- **SQS — Запитай сам (pull). SNS — Скажи всім (push).**
- Обробка двічі → visibility timeout. «Отруйні» повідомлення → DLQ. Порядок без дублів → FIFO.
- Потік з перемоткою → Kinesis Data Streams. Просто доставити в S3 → Firehose.

#### 🎯 Як питають на іспиті

- Замовлення губляться під час піків → **SQS між компонентами**
- Одна подія — три незалежні обробники → **SNS fan-out → три черги SQS**
- Фінансові транзакції строго по порядку → **SQS FIFO**
- Процес з ручним схваленням на кілька днів → **Step Functions Standard**
- Запускати задачу щоночі о 2:00 → **EventBridge Scheduler**

#### ⚠️ Не плутай

- SQS не видаляє повідомлення сам — споживач робить DeleteMessage після обробки.
- SNS — не черга: без SQS повідомлення можуть пропасти.
