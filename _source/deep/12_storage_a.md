### Три способи тримати дані

Образ з простого курсу — **три способи зберігати документи**:

::: fig storage-3 | Блочне — диск, прикручений до одного комп'ютера; файлове — спільна папка офісу; об'єктне — склад, куди звертаються через інтернет

### Блочне сховище: зошит з пронумерованими сторінками

**Блочне** сховище (block storage) — це «сирий» диск, поділений на пронумеровані **блоки**, як зошит зі сторінками. Операційна система сервера сама розмічає його під файли й папки.

- Підключається до **одного** сервера (як жорсткий диск у комп'ютері).
- Дуже **мала затримка**: можна змінити одну «сторінку», не чіпаючи решти.
- Для **операційної системи** й **баз даних**.

В AWS: **EBS** (мережевий диск для EC2) і **instance store** (локальні диски самого фізичного сервера).

### Файлове сховище: спільна шафа офісу

**Файлове** сховище (file storage) — звичні **папки й файли**, які одночасно бачать **багато** серверів по мережі. Як спільна шафа з папками в офісі, до якої мають доступ усі працівники.

- Працює через мережеві протоколи: **NFS** (для Linux, порт 2049) або **SMB** (для Windows, порт 445).
- Для спільних документів, вмісту сайтів, домашніх папок працівників, спільних даних для багатьох серверів.

В AWS: **EFS** (для Linux) і сімейство **FSx** (для Windows і спеціальних задач).

### Об'єктне сховище: безрозмірний склад

**Об'єктне** сховище (object storage) — **склад коробок з ярликами**. Кожен **об'єкт** — це файл разом з описом (метаданими) і унікальним **ключем**-адресою.

- Звертаються через **інтернет-запити** (HTTP API): «поклади коробку», «дай коробку».
- Місткість практично **безмежна**.
- Папок насправді немає: «папка» — лише частина ключа (`cakes/2026/tort.jpg`).
- Не можна змінити шматочок файлу — лише **замінити об'єкт цілком**. І не можна «змонтувати» такий склад як диск для бази даних.

В AWS: **S3** — про нього наступний розділ.

### Як міряють швидкість сховища

Ти вже знаєш ці слова — тепер про диски:

- **IOPS** («ай-опс») — скільки **окремих операцій** читання чи запису за секунду. Образ — **скільки коробок за секунду комірник виносить з комори**. Важливо для баз даних, де багато дрібних операцій.
- **Пропускна здатність** (throughput) — скільки **мегабайтів за секунду**. Образ — **скільки кілограмів за секунду** йде через двері. Важливо для відео, логів, аналітики — великих файлів.
- **Затримка** (latency) — скільки чекати **одну** відповідь.

І ще одна пара слів:

- **Випадковий доступ** — дрібні шматочки з різних місць (база даних шукає то одне замовлення, то інше). Потрібні високі IOPS — **SSD**.
- **Послідовний доступ** — великі шматки підряд (читаємо відео чи журнал від початку до кінця). Важлива пропускна здатність — тут згодяться й дешевші **HDD**.

### Постійне чи тимчасове

- **Постійне** (persistent) сховище переживає вимкнення сервера: EBS, EFS, FSx, S3.
- **Тимчасове** (ephemeral, «іфемерал») — зникає разом із сервером: **instance store**. Образ з простого курсу — **записи крейдою на дошці**: найшвидше, але стирається при зупинці. Лише для кешу й тимчасових даних.

### Що є що — одна таблиця

| | Блочне | Файлове | Об'єктне |
|---|---|---|---|
| Образ | диск одного комп'ютера | спільна шафа офісу | склад з ярликами |
| Хто користується | один сервер | багато серверів | будь-хто через інтернет |
| Як звертаються | як до диска | NFS / SMB | HTTP-запити |
| Обсяг | заданий розмір | росте за потребою | практично безмежний |
| Для чого | ОС, бази даних | спільні файли | фото, відео, бекапи, логи, озера даних |
| AWS | EBS, instance store | EFS, FSx | S3 |

> 🎯 Мнемоніка з простого курсу: **Блок — один сервер (EBS). Файли — багато серверів (EFS для Linux, FSx для Windows і HPC). Об'єкти — через HTTP (S3).**

#### 📖 Словничок

- **Блочне сховище** — «сирий» диск для одного сервера: EBS, instance store.
- **Файлове сховище** — спільні папки для багатьох серверів: EFS, FSx.
- **Об'єктне сховище** — склад об'єктів з ключами через HTTP: S3.
- **NFS / SMB** — мережеві протоколи спільних папок для Linux (порт 2049) / Windows (порт 445).
- **IOPS** («ай-опс») — операцій за секунду; **throughput** — мегабайтів за секунду; **latency** — час однієї відповіді.
- **Випадковий / послідовний доступ** — дрібні шматочки звідусіль / великі шматки підряд.
- **Persistent / ephemeral** — переживає вимкнення / зникає разом із сервером.

#### ✅ Головне

- **Блочне** — диск одного сервера (EBS, instance store): ОС і бази. **Файлове** — спільна шафа для багатьох (EFS — Linux/NFS, FSx — Windows/SMB і спецзадачі). **Об'єктне** — склад через HTTP (S3): безмежний, але не диск.
- **IOPS** — операції за секунду (бази, SSD); **throughput** — МБ/с (відео, логи, HDD); **latency** — час відповіді.
- **Випадковий** доступ → високі IOPS; **послідовний** → пропускна здатність.
- **Instance store** — тимчасовий («крейда на дошці»); решта — постійні.
- Мнемоніка: **Блок — один сервер. Файли — багато серверів. Об'єкти — через HTTP.**

### Bucket, об'єкт і ключ

**Amazon S3** («ес-срі», Simple Storage Service — простий сервіс зберігання) — об'єктне сховище AWS. Образ з простого курсу — **безрозмірний склад**:

- **Bucket** («бакет», відро) — **окремий склад** з назвою, **унікальною на весь світ** (бо вона стає частиною інтернет-адреси): `khmarynka-photos`. Назва — малими латинськими літерами, від 3 до 63 символів. Bucket живе **в одному регіоні**.
- **Object** (об'єкт) — **коробка**: сам файл плюс опис (метадані).
- **Key** (ключ) — **ярлик-адреса** коробки: `cakes/2026/tort-17.jpg`. «Папки» — лише частина ключа, яку консоль показує як папки. Частину ключа до останнього слеша називають **префіксом** (prefix).

Розміри:

- один об'єкт — до **50 TB** (з грудня 2025; раніше — 5 TB, і на іспиті може трапитися стара цифра);
- одним запитом можна завантажити до **5 GB**; для великих файлів — **multipart upload** (завантаження частинами паралельно; рекомендують від 100 MB, обов'язково понад 5 GB). Зірвалася одна частина — перевантажують лише її.

### Одинадцять дев'яток

S3 розраховано на надійність зберігання **99,999999999%** — «одинадцять дев'яток». Образно: з 10 мільйонів коробок у середньому губиться одна **за 10 000 років**. Для цього більшість класів тримає копії **щонайменше у трьох AZ**.

Ще кілька властивостей: доступність класу Standard — 99,99%; щойно записаний об'єкт одразу видно для читання (strong read-after-write consistency) — ніяких «зачекай хвилинку».

> ⚠️ Пам'ятаєш: **durability** (речі цілі) ≠ **availability** (двері відчинені). 11 дев'яток — це саме durability.

### Класи зберігання: будинок від передпокою до сховища в горах

Не всі речі потрібні однаково часто. Тому в S3 є **класи зберігання** — полиці з різною ціною: що рідше потрібна річ, то дешевше її тримати, але дорожче й довше діставати.

::: fig s3-house | Класи S3 — будинок від передпокою до сховища в горах: що нижче, то дешевше зберігати і довше діставати

| Клас | Образ | Для чого | Мін. строк оплати | Доступ |
|---|---|---|---|---|
| **Standard** | передпокій | часто потрібні дані | — | мілісекунди |
| **Intelligent-Tiering** | розумний комірник | доступ невідомий чи змінний | — | мілісекунди (архівні рівні — години) |
| **Standard-IA** | комора | рідко, але миттєво | 30 днів | мілісекунди + плата за отримання |
| **One Zone-IA** | комора в одному районі | рідко, дані можна відтворити | 30 днів | мілісекунди, лише одна AZ |
| **Glacier Instant Retrieval** | архів поруч | ~раз на квартал, але миттєво | 90 днів | мілісекунди |
| **Glacier Flexible Retrieval** | підвал | архіви й бекапи | 90 днів | від хвилин до годин |
| **Glacier Deep Archive** | сховище в горах | 7–10+ років для регулятора | 180 днів | до 12–48 годин |
| **Express One Zone** | касова стрічка | найшвидший, одна AZ | 1 година | одноцифрові мілісекунди |

Кілька важливих деталей:

- **Мнемоніка мінімальних строків: 30 · 90 · 180** (IA · Glacier · Deep Archive). Видалив раніше — однаково заплатиш за весь мінімальний строк.
- У Standard-IA, One Zone-IA і Glacier Instant Retrieval мінімальний розмір для оплати — **128 KB** (дрібний файл оплачується як 128 KB).
- **Glacier Flexible Retrieval** дістають трьома темпами: **Expedited** (1–5 хв), **Standard** (3–5 год), **Bulk** (5–12 год, безкоштовно). Гарантувати швидкий темп навіть у пік допомагає **provisioned capacity**.
- **Deep Archive**: Standard — до 12 годин, Bulk — до 48 годин.
- **Intelligent-Tiering** — **розумний комірник**: сам переносить об'єкти між рівнями (30 днів без звернень → «рідко», 90 → архівний миттєвий; за бажанням — і в глибші архіви). Бере невелику плату за нагляд, зате **без плати за отримання**. Ідеальний, коли **не знаєш**, як часто читатимуть дані.
- **One Zone-IA** і **Express One Zone** живуть в **одній AZ**: втратиш зону — можеш втратити дані. Лише для того, що можна відтворити (мініатюри, копії).

> 🎯 Рідко, але миттєво → **Standard-IA**. Невідомий патерн → **Intelligent-Tiering**. Роки для регулятора, 48 годин не страшно → **Deep Archive**. Відтворювані дані дешево → **One Zone-IA**.

### Lifecycle: речі самі переїжджають з віком

**Lifecycle rules** («лайфсайкл рулз», правила життєвого циклу) — **автоматичне переселення** речей з віком. Наприклад, для фото «Хмаринки»:

::: fig lifecycle | Lifecycle: фото автоматично «спускаються» дешевшими поверхами з віком, а через роки — видаляються

- через 30 днів — у Standard-IA;
- через рік — у Glacier Flexible Retrieval;
- через 10 років — видалити.

Правила вміють **переносити** (transition) і **видаляти** (expiration), зокрема старі версії об'єктів і незавершені завантаження частинами. У Standard-IA не можна перенести раніше ніж через **30 днів** після створення.

Як зрозуміти, коли переносити? **Storage Class Analysis** проаналізує, як часто читають дані, і підкаже. А **S3 Storage Lens** покаже загальну картину використання й витрат.

### Versioning: машина часу

**Versioning** («версіонінг») — **машина часу** для сховища: кожен перезапис створює **нову версію**, а стара лишається. Видалення лише ставить **delete marker** («позначку видалення») — стару версію можна повернути.

- Захист від випадкового видалення й перезапису (і від деяких вірусів-шифрувальників).
- **MFA Delete** — щоб остаточно видалити версію, потрібен код MFA (вмикає лише root).

### Replication: філія складу

**Replication** («реплікейшн») — автоматичне копіювання **нових** об'єктів в інший bucket:

- **CRR** (Cross-Region Replication) — в **інший регіон**: аварійне відновлення, близькість до клієнтів, вимоги законів;
- **SRR** (Same-Region Replication) — у **тому самому** регіоні: зібрати логи з кількох сховищ, копія робочих даних у тестовий акаунт.

Умови й деталі: versioning має бути **увімкнений з обох боків**; реплікуються лише **нові** об'єкти, а вже наявні — окремою операцією **S3 Batch Replication**; **Replication Time Control** (RTC) гарантує, що 99,99% об'єктів скопіюються за 15 хвилин.

### Object Lock: сейф з таймером

**Object Lock** («обджект лок») — **WORM**-захист (write once, read many — «записати раз, читати багато»): об'єкт не можна змінити чи видалити до кінця строку.

- **Compliance mode** — **ніхто**, навіть root, не видалить і не змінить до кінця строку. Для регуляторів.
- **Governance mode** — можуть обійти лише користувачі з особливим дозволом.
- **Legal hold** — «заморожено» без строку, доки не знімуть.

> 🎯 «Ніхто, навіть адміністратор, не може видалити чи змінити записи 7 років» → **Object Lock, compliance mode**.

### Безпека складу

- **Block Public Access** — «заборона публічного доступу» — **увімкнена за замовчуванням**. Щоб сховище стало публічним, її треба свідомо вимкнути.
- Старі списки доступу (ACL) за замовчуванням **вимкнені**; доступ дають **bucket policy** та IAM-політиками.
- **Шифрування**: SSE-S3 за замовчуванням, SSE-KMS для аудиту (розділ про шифрування).
- **Presigned URL** («пресайнд ю-ар-ел») — **тимчасовий пропуск на одну коробку**: посилання, що дозволяє скачати чи завантажити конкретний приватний об'єкт протягом заданого часу. Діє з правами того, хто його підписав.
- **Access Points** — окремі «входи» до великого складу для різних команд і застосунків, кожен зі своєю політикою (можна «лише з нашої VPC»). **Multi-Region Access Points** — один глобальний вхід до копій у кількох регіонах.
- **CORS** — дозвіл браузеру з іншого домену звертатися до сховища.

Приклад bucket policy, що забороняє будь-який доступ **без HTTPS**:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyHTTP",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": ["arn:aws:s3:::khmarynka-photos", "arn:aws:s3:::khmarynka-photos/*"],
    "Condition": { "Bool": { "aws:SecureTransport": "false" } }
  }]
}
```

Прочитай її самостійно: **Deny**, **усім** (`*`), **усі дії S3**, на сховище і всі об'єкти, **якщо** з'єднання не захищене. Ти вже вмієш це читати!

### Швидкість S3

- S3 витримує **3 500 запитів на запис і 5 500 на читання за секунду на кожен префікс**. Потрібно більше — розкладай ключі по **кількох префіксах** (`cakes/a/…`, `cakes/b/…`).
- **Multipart upload** — великі файли частинами паралельно.
- **Transfer Acceleration** — клієнти з далеких країн завантажують через найближчу edge-локацію, а далі — швидкою мережею AWS.
- **Byte-range fetches** — скачувати різні частини великого файлу паралельно.

### Ще кілька вмінь

- **Event notifications** — «щойно з'явився файл — повідом»: у SNS, SQS, Lambda чи EventBridge. Так фото торта автоматично стає мініатюрою.
- **Static website hosting** — S3 уміє сам роздавати простий статичний сайт, але лише по HTTP. Для HTTPS і власного домену ставлять **CloudFront + OAC** (сховище лишається приватним).
- **Requester Pays** — за завантаження платить той, хто завантажує (для великих публічних наборів даних).
- **S3 Batch Operations** — одна дія над мільярдами об'єктів: скопіювати, змінити теги, відновити з архіву, викликати функцію.
- **Inventory** — список усіх об'єктів з властивостями.
- S3 Select і S3 Object Lambda закриті для нових клієнтів — для запитів до даних у S3 використовують Athena (розділ про аналітику).

```lab Створи склад і поділися файлом через тимчасове посилання (10 хвилин)
Кілька мегабайтів у S3 коштують копійки; наприкінці ми все видалимо.

1. У консолі відкрий **S3** → **Create bucket**.
2. Назва — унікальна, малими латинськими літерами, наприклад `khmarynka-test-` + сьогоднішня дата + твої ініціали. Регіон — свій.
3. **Block Public Access** залиш увімкненим. Натисни **Create bucket**.
4. Відкрий bucket → **Upload** → додай будь-яке фото → **Upload**.
5. Спробуй відкрити **Object URL** з деталей об'єкта — отримаєш **AccessDenied**: сховище приватне.
6. Тепер обери об'єкт → **Actions** (або Object actions) → **Share with a presigned URL**, вкажи 5 хвилин і скопіюй посилання.
7. Відкрий його в браузері — фото показується. Через 5 хвилин те саме посилання перестане працювати.
8. Прибери за собою: видали об'єкт, потім **Delete bucket**.
```

#### 📖 Словничок

- **S3** («ес-срі») — об'єктне сховище: 11 дев'яток надійності.
- **Bucket** («бакет») — «склад» з унікальною на весь світ назвою, живе в регіоні.
- **Object / key / prefix** — «коробка» / її повна адреса / частина адреси до останнього слеша.
- **Multipart upload** — завантаження частинами (від 100 MB рекомендовано, понад 5 GB обов'язково).
- **Класи**: Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant / Flexible / Deep Archive, Express One Zone.
- **30 · 90 · 180** — мінімальні строки оплати IA · Glacier · Deep Archive.
- **Lifecycle rules** — автоматичні перенесення між класами й видалення.
- **Versioning / delete marker / MFA Delete** — машина часу / позначка видалення / видалення версій лише з MFA.
- **CRR / SRR / RTC** — реплікація в інший регіон / у той самий / гарантія «99,99% за 15 хв».
- **Object Lock** — WORM: compliance (ніхто), governance (з особливим дозволом), legal hold (без строку).
- **Block Public Access** — заборона публічного доступу, увімкнена за замовчуванням.
- **Presigned URL** — тимчасове посилання на приватний об'єкт.
- **Access Points** — окремі входи з власними політиками.
- **Transfer Acceleration** — прискорене завантаження через edge-локації.
- **Event notifications** — сповіщення про нові чи видалені об'єкти.

#### ✅ Головне

- **Bucket** (унікальна назва, регіон) → **об'єкти** з **ключами**; «папки» — префікси. Об'єкт до **50 TB**, запит до 5 GB, великі — **multipart**. **11 дев'яток** — durability.
- Класи: **Standard** → **Intelligent-Tiering** (невідомий доступ) → **Standard-IA / One Zone-IA** → **Glacier Instant / Flexible / Deep Archive**; мінімуми **30 · 90 · 180**; One Zone — лише відтворюване.
- **Lifecycle** — автоперенесення й видалення; **versioning** — машина часу; **CRR/SRR** — копії (потрібен versioning, нові об'єкти); **Object Lock compliance** — не видалить ніхто.
- Безпека: **Block Public Access** за замовчуванням, bucket policy + IAM, шифрування, **presigned URL**, Access Points; сайт з HTTPS → **CloudFront + OAC**.
- Швидкість: **3 500 / 5 500** запитів за секунду **на префікс**, multipart, **Transfer Acceleration**; події → SNS/SQS/Lambda/EventBridge.
